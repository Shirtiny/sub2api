# 套餐提前重置

## Goal

允许管理员按套餐配置用户是否可以提前重置订阅；用户在订阅页面主动确认后，立即重置当前套餐额度，同时将本次订阅的结束时间缩短配置的时长。

## Requirements

- 套餐编辑增加“提前重置”设置区。
- 支持启用/停用提前重置，并配置每次提前重置缩减的时长。
- 只有启用且缩减时长有效的套餐，订阅卡片才显示“提前重置”按钮。
- 用户操作必须通过危险色按钮和二次确认弹窗。
- 提前重置必须原子地重置当前订阅套餐额度，并缩减一个订阅周期（将当前订阅结束时间提前配置时长）。
- 后端必须校验订阅归属、订阅状态、套餐开关、缩减时长和剩余周期，拒绝导致无效订阅区间的请求。
- 成功后刷新订阅信息与额度展示，避免重复提交。

## Acceptance Criteria

- [ ] 管理员可保存和重新读取套餐的提前重置开关与缩减时长。
- [ ] 不允许提前重置的套餐不会向用户提供操作入口，后端也会拒绝绕过前端的请求。
- [ ] 用户确认提前重置后，已用额度归零/恢复到新周期状态，订阅结束时间按套餐配置提前。
- [ ] 操作失败展示现有统一错误提示，成功展示成功提示并刷新卡片。
- [ ] 数据库迁移、后端测试、前端类型检查及相关测试通过。

## Cross-layer Contract

- 套餐字段：`early_reset_enabled: boolean`、`early_reset_duration_days: integer`。
- 用户操作：对当前订阅 ID 发起提前重置请求；请求体为空。
- 成功响应：返回更新后的订阅 DTO。
- 典型错误：订阅不存在/不属于当前用户、订阅非 active、套餐未启用、缩减天数无效、剩余周期不足、并发更新冲突。
- Good：active 订阅、套餐启用、缩减天数为正且结束时间缩减后仍晚于开始时间/当前时间。
- Base：套餐未启用时不显示按钮，直接调用接口返回业务错误且不改数据。
- Bad：重复/并发请求不能造成额度和结束时间被非原子地部分更新。

## Technical Notes

- 遵循现有 handler → service → repository/Ent 分层与统一响应格式。
- 复用现有订阅额度重置、确认弹窗和通知模式。
- 保留工作区中已有未提交改动，只做增量修改。
